- **Callers that handle a failed metadata call:** a call whose checkpoint fails now throws and leaves the open store as it was before the call. The one exception is a failed branch creation's ID, which the open store doesn't give out again. The metadata calls are `registerState()`, `updateStateStrategy()`, the branch creations, `switchBranch()` and `deleteBranch()`. Before, the change stayed in memory, and the next good checkpoint published it and told subscribers. Now a subscriber hears of a branch change only when its call succeeds.
  - **Migration:** after such a throw, make the same call again once the cause is mended. A retry no longer gets `BranchExists` or `StateExists` because of the call that failed. A caller that reads the store after a throw also needs no change.
  - **Unchanged:** existing stores keep opening, since the on-disk format is the same. A later write of a record or a state, a field-index registration and a metadata call still save the owed checkpoint first. A blob write does not save it. Until that save, the disk can still hold part of the failed change. If the process stops before that save, the next open can show that part.
- **Rust callers of `StateManager`:** `retire_branch` no longer releases a branch's caches and counts at once. It sets the branch's field indexes aside, and `purge_retired_branches` releases them with the rest.

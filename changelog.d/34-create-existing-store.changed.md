- Opening a directory with no `MANIFEST` now fails with `InvalidFormat` naming the directory, and saying whether it holds a damaged store's files or no store at all, instead of a bare `IO error: No such file or directory` that named neither. A path that doesn't exist stays an IO `NotFound`, now naming the path, and a look that fails is an IO error naming where (#34).
- `Store::open_or_create` and `JsStore.openOrCreate` on an existing directory with no `MANIFEST` used to fail with that bare IO `NotFound`. A directory with a store's data files, or a `blobs/` with data in it, now fails with `InvalidFormat` as a damaged store. One holding anything else a new store can't sit beside fails with `InvalidFormat` naming the entry, whichever `create_if_missing` says, and one that can't be listed fails with an IO error naming it. Otherwise, with `create_if_missing` unset, it fails with `NotInitialized`, and with it set the store is created there (#34).

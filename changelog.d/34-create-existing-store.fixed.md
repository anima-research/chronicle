- `Store::create` (and `JsStore.create`) on a directory that already holds a store no longer resets it. It used to keep the records but publish empty state and branch indexes over the store's own at the first sync, losing every registration and branch with no error; it now refuses with `InvalidOperation`, naming the path and the file it found. It also takes the store's lock before writing anything, so a create aimed at a store another process has open no longer rewrites that store's `MANIFEST` before failing with `Locked` (#34).
- `Store::open_or_create` on an existing empty directory (a pre-created volume or mount point) now creates the store there when `create_if_missing` is set, instead of failing to open it (#34).

- `Store::create` (and `JsStore.create`) on a directory that already holds a store no longer resets it. It used to keep the records but publish empty state and branch indexes over the store's own at the first sync, losing every registration and branch with no error. It now refuses with `InvalidOperation`, naming the path, both for a store and for a damaged one (its `records.log`, `state.bin` or `branches.bin` without a `MANIFEST`). It also takes the store's lock before writing anything, so a create aimed at a store another process has open no longer rewrites that store's `MANIFEST` before failing with `Locked`, and it writes `MANIFEST` atomically, so a crash can't leave one cut short (#34).
- `Store::open_or_create` on a directory without a `MANIFEST` that holds nothing but `lost+found` (a fresh volume's root), Finder's `.DS_Store`, or the `LOCK` and `blobs/` of a create that stopped before its manifest now creates the store there (with `create_if_missing`), instead of failing to open it (#34).

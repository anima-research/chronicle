- **Hosts that open a store on an existing empty directory:** with `create_if_missing`, which `JsStore.openOrCreate` always sets, `Store::open_or_create` now creates a store in a directory that's empty or holds only `lost+found` or `.DS_Store`, where it used to fail. So a store started before its volume mounts (an unmounted mount point is an empty directory) now creates a fresh empty store that the volume hides once it mounts, and a pre-flight check that opens a path to see whether it's a store now makes one. **To act:** if you relied on that failure, check the mount or the directory before opening. connectome-host's store audit is one such caller. **Unchanged:** existing stores keep opening, and a missing directory is still created (#34).

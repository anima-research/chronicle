- `Store::open` and `Store::open_or_create` refuse with `Corruption` a used store that has lost its `records.log`. In the Node API these are `open` and `openOrCreate`. A used store is one that holds `state.bin` or `branches.bin`. The error names the missing file, and the open creates no `records.log`. They used to create an empty `records.log`. If a state head pointed into that empty log, the open refused and blamed a torn tail or a corrupt `state.bin`. If no state head did, the store opened with no records. A directory with a `MANIFEST` and none of the other three files still opens and gets its log. Stores that still have their `records.log` open as before.
- An empty `records.log` that such an earlier open left behind is refused with `Corruption` too, when `state.bin` holds a state head or `branches.bin` holds a branch head above 0. Its words call the log empty. With branch heads alone, the store used to open and set each head back to its branch point, which is 0 for `main`. The next sync then saved those heads.
- In any store, the open refuses with `Corruption` when `records.log`, `state.bin` or `branches.bin` is a symbolic link to nothing. The error names the link, and the open creates nothing where it leads. A `state.bin` or `branches.bin` link to nothing used to read as an absent file, and the store opened without the state registrations or the branches that the file held.
